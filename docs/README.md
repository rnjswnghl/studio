# 과제 5 · CUT&NOTE 편집 작업의 탐색과 보호 개선

이 문서는 사용자 요청, 설계 판단, 실제 구현, 검증 증거를 구분한다. 미구현 동작을 완료했다고 쓰지 않고, 실험 측정값을 추정하지 않는다.

## 읽는 순서

1. [변경 설계](changes.md): 문제 → 요구사항 → 설계 이유 → 변경 위치 → 검증 결과.
2. [고정 검사 10개](checks.md): A/B가 동일하게 실행하는 입력과 관찰 가능한 기대값.
3. [실험 조건](experiment.md): 공통 상한과 측정 정의, 버전 기록.
4. [인수인계](handoff.md): A가 전달한 원문 보존본. 당시 상태와 남은 작업.
5. [B 완료 기록](b-completion.md): 최종 검증, 실행 구간, 요청 수, 오류 회차와 버전.

## 주제

기존 편집기의 ‘원하는 구성 찾기, 같은 소재 구분하기, 배치 실수 방지하기’를 개선한다. 템플릿 검색, 스티커 잠금, 편집용 격자, 반복 요소 번호를 하나의 편집 흐름 개선으로 묶는다. 새 서비스나 전체 UI 개편은 범위에 포함하지 않는다.

## 근거의 수준

- 사용자 요구: 검색·잠금 추가, 켜고 끄는 격자, ‘하트 스티커 1/2’처럼 반복 요소 구분, 상세한 변경 문서.
- 코드 관찰: `renderTemplates()`는 내 템플릿 전체를 나열한다. `syncLayerControls()`는 스티커의 소재 이름만 표시한다. 드래그·방향키·슬라이더·퀵 도구가 각각 레이어를 수정한다. `draw()`는 미리보기 캔버스와 출력 캔버스를 구분한다.
- 설계 판단: 여러 수정 경로를 모두 막는 잠금, 순서 변경에도 유지되는 번호, 출력에 포함되지 않는 격자가 필요하다. 이는 구현자의 판단이며 사용자 테스트나 사용성 통계로 검증된 결론은 아니다.

## 제출 상태

공개 비교 보고서와 실제 배포 확인은 A/B 실험 완료 후 작성한다. 현재 문서는 대화 전문을 포함하지 않는다. 본인의 최종 도구 선택 기준은 측정 결과를 확인한 사용자가 판단해야 한다.
