# 변경 설계와 구현 근거

## 1. 내 템플릿 이름 검색

### 문제와 요청

현재 `app.js`의 `renderTemplates()`는 저장한 템플릿을 모두 보여준다. 사용자가 저장한 구성을 이름으로 찾을 수 있도록 검색을 추가한다.

### 동작 기준

- ‘저장’ 탭의 내 템플릿 목록만 검색한다. 기본 템플릿 선택은 유지한다.
- 이름의 부분 문자열을 비교하며 앞뒤 공백, 영문 대소문자, Unicode 정규화 차이를 흡수한다.
- 검색 결과가 없을 때와 저장한 템플릿 자체가 없을 때를 구분한다.
- 전체 개수와 결과 개수를 구분한다. 검색 초기화는 템플릿을 삭제하지 않는다.
- 검색 결과에서 선택·수정·삭제할 수 있고, 이름 변경 후 결과가 즉시 갱신된다.
- 검색어는 작업 데이터가 아닌 임시 탐색 상태다. 새로고침하면 검색어는 비워지고 저장한 템플릿은 유지된다.

### 설계 이유

이름 검색으로 찾기 위한 동작을 줄인다. 임시 검색어를 JSON 프로젝트에 넣지 않아 편집 데이터와 탐색 상태의 책임을 나눈다. DOM에 이름을 표시할 때 기존 이스케이프 처리를 유지한다.

### 변경 위치와 결과

실제 변경: `index.html`의 저장 탭에 검색 입력·지우기·결과 개수 상태를 추가했다. `app.js`의 `renderTemplates()`가 `templateQuery`로 내 템플릿 목록만 필터링한다. 이름과 검색어 양쪽에 NFC 정규화, trim, 소문자 변환을 적용한다. 기존 CRUD가 같은 렌더 함수를 호출하므로 이름 변경·삭제 후 검색 결과가 갱신된다. `styles.css`는 기존 다크 패널의 색·크기와 맞춘다.

검증: A의 고정 T05-01과 T05-02가 통과했다. 새 검색어는 state에 넣지 않았기 때문에 프로젝트 JSON에 보존되지 않는다. 기존 `escapeHtml()`을 유지하여 검색 결과의 사용자 입력이 HTML로 해석되지 않는다.

## 2. 스티커 레이어 잠금

### 문제와 요청

스티커는 캔버스 드래그뿐 아니라 방향키, 슬라이더, 정밀 수치 입력, 퀵 도구로도 수정된다. 사용자는 선택한 레이어의 우발적 변경을 막고자 한다.

### 동작 기준

- 잠금은 개별 스티커 레이어에 적용한다. 텍스트·사진·프레임 잠금은 이번 범위 밖이다.
- 잠긴 스티커도 목록과 캔버스에서 선택하여 잠금 해제할 수 있다.
- 이동·회전·크기·불투명도·좌우 반전·삭제·복제·앞뒤 순서 변경을 막는다.
- 잠긴 스티커를 클릭하거나 드래그하면 아래 사진이나 다른 요소가 대신 움직이지 않는다.
- 잠금/해제는 실행 취소·다시 실행 대상이며 자동 저장·내 템플릿·JSON 백업에서 유지된다.
- 기존 백업에 `locked`가 없으면 잠금 해제로 처리한다. 있으면 boolean만 허용한다.

### 설계 이유

버튼 비활성화만으로는 키보드와 직접 이벤트 경로가 남는다. UI 상태와 변경 핸들러 양쪽에서 보호한다. 기존 ID를 잠금 키로 사용하여 동일 소재 복제본도 독립적으로 보호한다.

### 변경 위치와 결과

예정 위치: `editing.js`, `app.js`, `quick-edit.js`, `index.html`. B가 구현 후 실제 근거와 결과를 기록한다.

## 3. 켜고 끄는 편집용 격자

### 문제와 요청

자유 배치에 위치 기준이 부족하다. 사용자는 격자 선을 필요할 때만 켜고 끄는 방식을 제안했다.

### 동작 기준

- 기본은 꺼짐. 버튼으로 켜고 끄며 접근성 상태를 표시한다.
- 실제 캔버스 영역에 가로·세로 10등분 가이드와 중심선을 표시한다.
- 세 비율 및 반응형 화면에서 캔버스 기준으로 표시한다.
- 격자는 드래그를 가로막지 않으며 자동 맞춤이나 좌표 변경은 수행하지 않는다.
- PNG·JPEG·PDF 및 JSON/내 템플릿에는 격자를 넣지 않는다.

### 설계 이유

격자는 결과물의 구성 요소가 아닌 편집 보조 표시다. `draw()`의 미리보기 전용 경로에만 추가해 출력이 변하지 않게 한다. 자동 맞춤은 사용자의 정밀 배치를 바꿀 수 있으므로 명시적으로 제외한다.

### 변경 위치와 결과

실제 변경: `app.js`에 state와 분리한 `gridVisible`과 `drawGrid()`를 추가했다. 미리보기 캔버스인 `target===canvas`인 경우에만 격자를 그리며, 10등분 선은 반투명 회색, 중심선은 청록색으로 구분한다. 선 좌표를 캔버스 너비·높이에서 계산해 세 비율에 대응한다.

`index.html`에는 `aria-pressed`와 `aria-controls`가 있는 버튼을 추가했다. 별도 DOM 오버레이를 만들지 않아 포인터 이벤트가 기존 캔버스에 전달된다. `styles.css`에 켜짐 상태와 모바일 버튼 스타일을 추가했다. 내보내기는 기존 별도 캔버스를 사용하며 격자는 여기서 그리지 않는다.

검증: A의 고정 T05-08과 T05-09가 통과했다. 세 비율에서 격자 켜짐/꺼짐 픽셀이 달라지고 드래그가 가능했다. 동일 구성의 격자 꺼짐/켜짐 PNG·JPEG·PDF 바이트가 각각 일치하여 가이드가 출력에 들어가지 않음을 확인했다.

## 4. 반복 요소 번호

### 문제와 요청

`syncLayerControls()`는 같은 소재의 레이어를 같은 이름으로 표시한다. 사용자가 ‘하트 스티커 1’, ‘하트 스티커 2’처럼 구분하는 방식을 요청했다.

### 동작 기준

- 스티커는 최초 추가부터 ‘소재 이름 1’로 표시한다. 같은 표시 이름의 다음 스티커는 2, 3…으로 표시한다.
- 레이어 ID에 연결한 번호를 보존한다. 앞뒤 순서를 바꾸거나 다른 스티커를 삭제해도 살아 있는 번호를 바꾸지 않는다.
- 복제본은 새 ID와 새 번호를 얻으며, 현재 같은 이름의 최대 번호보다 큰 번호를 사용한다.
- 같은 파일명을 가진 사용자 스티커도 서로 다른 번호로 구분한다.
- 텍스트는 같은 내용의 반복 요소를 번호로 구분하며 번호는 텍스트 ID에 연결한다.
- 기존 작업에는 번호를 부여하여 호환한다. 자동 저장·템플릿·JSON·실행 취소에서 번호가 보존된다.
- 번호는 화면 식별자이며 삭제 후 연속성이 끊겨도 문제없다. 영구적인 삭제 번호 예약까지는 요구하지 않는다.

### 설계 이유

화면의 현재 목록 순서로 번호를 매기면 순서 변경마다 이름이 바뀐다. 생성된 항목의 식별 번호를 데이터에 보존하여 선택 중인 항목을 안정적으로 인식하게 한다.

### 변경 위치와 결과

예정 위치: `editing.js`, `text.js`, `app.js`. B가 구현 후 실제 근거와 결과를 기록한다.
