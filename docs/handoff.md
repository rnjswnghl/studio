# CUT&NOTE · A 중단 → B 인수인계

## 1. 목표

기존 편집 흐름의 내 템플릿 검색, 스티커 레이어 잠금, 켜고 끄는 격자, 반복 스티커·텍스트 번호를 완성한다. 상세 요구는 `docs/changes.md`, 고정 검사 정확히 10개는 `docs/checks.md`와 `scripts/qa-t05.cjs`에 있다. 동일 최초 요청과 공통 상한은 `docs/experiment.md`에 보존했다.

사용자가 직접 고른 다음 도구 선택 기준: ‘인수인계 문서의 정확성과 새 대화에서 이어받는 능력을 가장 중요하게 본다.’

## 2. 현재 상태와 버전

제공 저장소 폴더: `studio-b`. 소스 버전 ID: `3d57de3991fcc1d2b6b70d229608972ea6c9ccde`. 태그: `t05-a-handoff`. 브랜치: `task5-editing`. `git rev-parse HEAD`가 이 ID와 정확히 같아야 한다.

검사·상한을 구현 전에 고정한 준비 커밋: `5e21766e267c10ee49500343f60f0e58878f2a6a`. 검사 스크립트의 Git blob ID: `04a0f8b8879b2240ffd73730f4a7b4291c3c3b83`.

A가 검색·격자를 구현한 계획된 지점에서 중단했다. 내 템플릿 검색은 NFC/공백/대소문자 정규화와 수정·삭제 후 갱신을 지원한다. 격자는 `gridVisible`로 미리보기에만 그리며 출력·JSON에는 포함하지 않는다. 잠금과 반복 번호는 아직 구현하지 않았다.

## 3. 실행 명령

프로젝트 루트에 있다면 먼저 `Set-Location studio-b`를 실행한다. 모든 아래 명령은 저장소 폴더 안에서 실행한다.

```powershell
git rev-parse HEAD
git hash-object scripts/qa-t05.cjs
node --test tests/core.test.js tests/editing.test.js tests/text.test.js
node scripts/build.mjs
$env:T05_STAGE = 'b-final'
node scripts/qa-t05.cjs
```

환경: Windows, Node 24.19, Edge, 번들 Playwright. 이 환경은 `npm` 명령이 PATH에 없다. 위 검사는 의존성 설치 없이 실행한다. QA는 Node HTTP 서버를 임의의 로컬 포트에 자동으로 열고 종료한다. Playwright를 일반 설치에서 찾지 못하면 Node 런타임 옆 번들 경로를 사용한다. 다른 환경에서는 Playwright와 Edge를 설치하거나 `PLAYWRIGHT_MODULE`을 지정한다. 초기 에셋 준비에는 시간이 걸리므로 스크립트의 초기화 대기 설정을 유지한다.

로컬 앱을 직접 띄울 때는 일반 npm 설치 환경의 `npm ci`, `npm run dev`를 사용한다. 빌드 결과는 `dist/`, QA 결과는 Git에서 제외되는 `qa/`다. 외부 API, 비밀키, DB는 필요하지 않는다. 웹폰트 연결 실패 시 앱은 기본 글씨체 안내를 제공한다.

## 4. 통과 검사와 재현 증거

A 최종 고정 검사 4/10 통과: T05-01, T05-02, T05-08, T05-09. 기존 Node 검사 14/14 통과. `node scripts/build.mjs` 성공.

새 폴더에 Git clone한 동일 버전에서도 기존 14/14, 빌드 성공, 고정 검사 4/10으로 동일하게 재현했다. 새 폴더의 `git rev-parse HEAD`와 검사 blob ID도 위와 일치했다. 첫 빌드 시 저장소 밖에서 실행해 경로 오류가 한 번 발생했고, 작업 폴더로 이동한 뒤 정상 재현했다. 이 문제를 방지하려고 실행 명령에 작업 폴더 이동을 명시했다.

A 최종 증거: `docs/evidence/a-final.json`. 새 폴더 재현 결과는 제공 폴더 `qa/t05-a-fresh-reproduction-*.json`과 함께 저장되어 있으며, 최종 보고서에는 해당 집계 증거를 보존한다.

## 5. 남은 문제

- T05-03/04/05/10: `#lockLayer`와 잠금 보호·저장·복원 기능이 없다.
- T05-06/07: 동일 소재 이름과 같은 텍스트가 번호 없이 표시된다.
- `app.js`의 스티커 변경 경로는 슬라이더/수치 입력, 방향키·Delete, 캔버스 이동/회전/크기, 복제·반전·순서 변경, `quick-edit.js`의 퀵 도구로 나뉜다. UI 비활성화뿐 아니라 각 핸들러에도 잠금 검사가 필요하다.
- 같은 파일명 사용자 스티커는 서로 다른 key를 가져도 화면 이름이 겹칠 수 있다. 텍스트 내용 수정 뒤 같은 이름 그룹에 번호가 충돌하지 않도록 해야 한다.
- 기존 백업은 번호·locked 필드가 없을 수 있다. 호환성과 손상 입력 거부를 함께 유지한다.

## 6. 다음 행동

1. B 시작 시각, 실제 사용자 작업 요청 1회, 시작 커밋, 공통 상한, 제공받은 문서 SHA-256을 기록한다. 문서 버전과 실제 HEAD를 대조한다. 이전 대화는 조회하지 않는다.
2. 스티커 잠금·반복 스티커/텍스트 번호를 구현한다. 번호는 ID에 연결하고 순서 변경·저장·실행 취소에서 유지한다. 잠긴 항목을 캔버스에서 선택하고 잠금 해제할 수 있게 한다.
3. 같은 고정 검사 10개와 기존 회귀 검사, 빌드를 실행한다. 검사 실행 회차 중 FAIL이 있는 회차 수를 오류 수로 기록한다. `qa/` 결과를 검토한 후 모델 이름·개인 경로 없이 `docs/evidence/`에 보존한다.
4. `docs/changes.md`에 문제→설계 이유→실제 변경 위치→검증 증거를 추가하고 `README.md`의 A 단계 진행 문구를 최종 상태로 갱신한다. 이 제공 문서를 변경 없이 `docs/handoff.md`에 보관해 A 작성과 B 수신 내용의 동일성을 남긴다.
5. 실제 시간·요청 수·오류 회차·검사 통과 수·버전·누락 여부를 기록하고 커밋한다. 완료 커밋과 결과를 최종 답변에 보고한다. 누락이 없으면 ‘없음’, 있으면 변경 전후를 기록한다. 실측하지 못한 수치는 추정하지 않는다.

B의 상한도 실제 작업시간 45분·사용자 작업 요청 10회다. 도구 호출은 별도 기록하며 측정할 수 없으면 ‘미측정’으로 표시한다. 이 실험은 단계별 작업 범위가 달라 모델 우열을 단순 비교하지 않는다.

## 7. 건드리지 말 것

- 검사 10개 ID·입력·기대값·검사 스크립트를 삭제/완화/수정하지 않는다.
- 공통 시간·요청 상한과 최초 요청을 바꾸지 않는다.
- A 구현의 검색·격자 출력 제외 동작을 유지한다.
- 사진·프레임·텍스트 출력과 기존 JSON 복원, 개인정보 외부 전송 금지 동작을 유지한다.
- 원본 에셋이나 사용자 데이터를 임의로 삭제하지 않는다. QA는 새 브라우저와 합성 입력만 사용한다.
- A 대화 전문이나 다른 채팅을 요청하지 않는다. 저장소와 이 인수인계 문서만 사용한다.
- 원격 push, PR 생성, 배포는 인수인계 완료 후 담당 대화에서 처리한다. B는 로컬 작업과 검증·커밋을 완료한다.
