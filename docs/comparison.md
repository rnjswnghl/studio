# 과제 5 · 대화가 끊겨도 이어지는 CUT&NOTE 개선

저장소와 인수인계 문서만 받은 새 B 대화가 남은 기능을 완성했다. 최종 고정 검사 **10/10**, Node 검사 **17/17**, 추가 브라우저 검사 **3/3**, 기존 브라우저 회귀와 빌드가 통과했다.

- 공개 비교 보고서: https://cutandnote.rnjswnghl.chatgpt.site/docs/index.html
- 제출 소스: https://github.com/rnjswnghl/studio/tree/t05-submission
- 상세 변경 이유와 코드 근거: [changes.md](changes.md)

## 무엇을 개선했는가

1. 내 템플릿 이름 검색: 한글·영문, 부분 문자열, 공백·대소문자·Unicode 차이를 처리하고 수정·삭제 후 결과를 갱신한다.
2. 스티커 레이어 잠금: 선택과 해제는 허용하며 이동·회전·크기·불투명도·반전·삭제·복제·순서 변경을 막는다. 자동 저장·템플릿·JSON·실행 취소에도 적용한다.
3. 편집용 격자: 10등분·중심선을 켜고 끈다. PNG·JPEG·PDF와 JSON에는 포함하지 않는다.
4. 반복 요소 번호: 동일 스티커·동일 파일명·같은 텍스트를 번호로 구분하고 순서 변경·저장·복원 시 항목 ID의 번호를 유지한다.
5. 모바일에서 소재 탭을 항상 열 수 있도록 접근 경로와 상태 속성 충돌을 수정했다.

## 이름을 가린 측정 비교

| 측정값 | A | B |
|---|---|---|
| 실제 활성 작업시간 | 8분 52초 | 14분 29초 |
| 사용자 작업 요청 / 상한 | 1 / 10회 | 2 / 10회 |
| 오류 회차 수 | 2회 | 2회 |
| 고정 검사 최종 통과 | 4 / 10 | 10 / 10 |
| 공통 시간 상한 | 45분 | 45분 |
| 도구 호출 수 | 미측정 | 미측정 |

A는 검색·격자를 완성하고 잠금·번호를 남겨 계획대로 중단했다. A의 실패 회차에는 이 미구현 검사가 포함된다. B는 잠금·번호와 모바일 접근을 완료했다. 서로 다른 시작 상태와 작업 범위를 가진 순차 인수인계 실험이므로 이 표만으로 모델의 일반적인 우열을 판단하지 않는다.

요청 수는 사용자 작업 요청이다. 도구 호출 수와 혼동하지 않는다. 오류 수는 고정 검사 10개 중 하나 이상 FAIL인 전체 실행 회차 수다. 검사 삭제·완화·기대값 변경은 모두 0건이다. 공통 최초 요청과 상한은 [experiment.md](experiment.md)에 구현 전 보존했다.

## 중단과 시간 기록

A는 2026-10-13에 시작→계획된 중단→새 폴더 재현과 문서 전달을 수행했다. B의 첫 대화는 같은 날 시작했고 사용량 제한으로 중단됐다. 실행 중인 검사는 중단 뒤 2026-10-13 21:53:13 KST에 10/10으로 완료됐다. 2026-10-14에 같은 B 대화를 재개하여 문서와 새 최종 검증을 마쳤다. 대화 전문은 제공하지 않았다.

B 자체 기록은 12분 26초다. 위 비교표는 첫 앱 실행 시작부터 백그라운드 QA 종료까지와 재개 turn 전체 시간을 합친 **14분 29초**를 사용한다. 처음 문서 읽기·최종 응답·백그라운드 검사를 포함하는 보수적인 관측값이다. 비활성 사용량 제한 대기는 별도 보존하며 실제 활성 작업시간에서 제외한다. 앱 시작 시각의 정밀도는 초 단위다. [원본 B 측정](evidence/b-session.json), [관측 구간 계산](evidence/b-observed-timing.json).

A 시작→A 인수인계→B 시작→B 완료 순서를 보존했다. 전달·수신 문서 SHA-256은 모두 `4CBA43341C2EC034493D49583E5B666DD048990E2B889D1143795C37E4099795`다. 인수인계 누락으로 앞 대화를 요청한 적이 없으며 기능 요구 누락은 없음으로 기록됐다. Windows Git 줄바꿈 변환으로 전달 문서 바이트가 달라지지 않도록 해당 파일에만 변환 제외 속성을 적용했다.

## 짧은 확인 방법 · 4줄

위치: 공개 CUT&NOTE 스튜디오를 연다.  
3단계 행동: 같은 하트를 두 개 추가 → 레이어 목록에서 하나를 잠금 → 잠긴 하트를 캔버스에서 드래그한다.  
통과 모습: 같은 소재가 1·2로 구분되고 잠금 표시가 있으며, 잠긴 하트는 움직이지 않는다.  
안 될 때 모습: 같은 소재의 이름이 구분되지 않거나, 잠긴 하트의 위치가 변한다. 전체 판정은 고정 검사 10개 결과를 확인한다.  

## AI와 나의 판단 · 3줄

AI에게 맡긴 일: 검사·코드·인수인계 문서·변경 근거 작성, 새 폴더 재현, 검증과 배포.  
내가 직접 판단한 일: 스튜디오 프로젝트와 개선 범위, 반복 요소 번호 표시 방식, 다음 도구 선택에서 인수인계 정확성과 이어받기 능력을 우선하는 기준.  
AI 제안을 따르지 않은 일: 정렬·맞춤선 제안 대신 필요할 때 켜고 끄는 격자 가이드를 선택했다.  

## 다음 작업의 도구 선택 기준

인수인계 문서의 정확성과 새 대화에서 이어받는 능력을 가장 중요하게 본다.

공개 보고서와 증거에는 실제 이름·생일·개인 경로·인증 토큰·비밀값·대화 전문을 포함하지 않는다. 시험 입력은 합성 이름·이미지이며 결과와 소스는 로그인 없이 열리는 공개 주소를 사용한다.
