# A/B 실험 조건 · 구현 시작 전 고정

## 동일 최초 요청

> CUT&NOTE의 기존 편집 흐름을 개선하세요. 내 템플릿 이름 검색, 스티커 레이어 잠금, 켜고 끄는 편집용 격자, 반복 스티커·텍스트의 번호 표시를 구현하세요. docs/changes.md의 동작 기준과 docs/checks.md의 고정 검사 10개를 따르세요. docs에 문제·요구·설계 이유·코드 근거·실제 검증 결과를 기록하세요. 기존 기능과 백업 호환성을 유지하고 검사 삭제·완화·기대값 변경은 하지 마세요. 공통 상한은 실제 작업시간 45분, 사용자 작업 요청 10회입니다. 저장소와 인수인계 문서만으로 실행하고, 대화 전문에 의존하지 마세요.

## 공통 상한과 측정 정의

- 실제 작업시간: 각 AI 시작 기록부터 중단/완료 기록까지의 경과시간. 구현·검사·인수인계 작성 시간을 포함한다. 시작 전 요구 수집·저장소 조사·검사 작성은 준비 단계로 별도 표기한다.
- 시간 상한: 각각 45분. 무료 한도 소진을 유도하지 않는다.
- 요청 상한: 각각 사용자 작업 요청 10회. AI가 자율적으로 수행하는 도구 호출은 별도 수치이며 요청에 섞지 않는다.
- 최초 작업 요청은 저장된 위 문장 1회로 시작한다. 후속 수정 요청은 횟수에 추가한다.
- 도구 호출: 내부 실제 실행된 도구 호출 수. 중첩 실행 wrapper와 내부 실행을 이중 계산하지 않는다. 확보할 수 없는 수치는 ‘미측정’으로 표시한다.
- 오류 회차 수: 고정 검사 10개 중 하나 이상 FAIL인 실행 회차 수. 실패한 검사 개수와 다르다.
- 통과 수: 고정 10개 중 PASS 수. 환경 실패는 통과로 간주하지 않는다.
- 재작업량: 제출 후 별도 추정하지 않는다. A/B 각 시작·종료 커밋에서 lockfile 제외 추가·삭제 줄 수를 산출한다.

## 예정 순서

1. 준비 커밋에 최초 요청·검사 10개·공통 상한을 보존한다.
2. A 시작을 기록하고 검색·격자를 구현한다. 고정 검사 10개를 전부 실행한다.
3. 검색·격자를 검증한 지점을 계획된 중단으로 삼는다. 잠금·번호를 B의 남은 기능으로 보존한다.
4. A 중단 버전과 7항목 인수인계 문서를 저장한다. 새로운 폴더에서 실행을 재현한다.
5. 다른 모델의 새 대화 B에 저장소와 동일한 인수인계 문서만 제공한다. 최초 요청은 위 문장을 그대로 사용한다.
6. B가 잠금·번호를 구현하고 같은 검사 10개 및 필요한 기존 회귀 검사를 실행한다.
7. 모델 이름을 가린 비교표, 실제 소스 버전, 짧은 확인법, 본인 판단을 제출한다.

## 비교의 한계

이것은 동일 초기 코드에서 각각 독립 구현하는 벤치마크가 아니라 순차 인수인계 실험이다. A와 B의 작업 범위가 다르므로 시간만으로 모델의 일반적인 우열을 판단하지 않는다.
